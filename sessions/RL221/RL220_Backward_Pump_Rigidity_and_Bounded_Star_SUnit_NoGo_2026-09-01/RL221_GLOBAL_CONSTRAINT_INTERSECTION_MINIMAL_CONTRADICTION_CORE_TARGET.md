# RL221 — Global Constraint Intersection / Minimal Contradiction Core

This target supersedes the previously prepared RL221 local-thread successor by explicit user instruction at RL220 closeout. It does not alter, weaken, or reinterpret any RL220 mathematics, proof-state classification, certificate, correction/demotion, barrier, or numerical outcome.

## Purpose

RL221 is deliberately **not another incremental attack on the current local thread**, not another global audit, not another route tournament, and not another roadmap-ranking exercise.

Its purpose is to ask a substantially different question:

> After more than 200 research sessions, do the currently valid independent theorems, exact certificates, structural restrictions, arithmetic constraints, forbidden regions, required regions, ownership conditions, divisibility conditions, H21 restrictions, radius obstructions, Gate-A/Gate-B facts, blue-basin facts, 2-adic restrictions, rank/height laws, phase/full-cycle identities and other surviving weapons already form an inconsistent system when imposed simultaneously on one hypothetical RL counterexample?

The session should attempt to discover a **minimal contradiction core** from the existing body of mathematics.

The central object of study is not an individual historical route. It is a single hypothetical genuine RL/nontrivial-cycle object required to satisfy **all applicable currently valid constraints simultaneously**.

## Strategic distinction from previous global audits

RL72, RL75, RL99 and related sessions already performed global audits, lemma catalogues, route tournaments, dependency reviews, synthesis and roadmap setting.

Do not repeat those exercises.

In particular, do not spend RL221 merely answering:

- what has been proved;
- which routes remain open;
- which route should be ranked first;
- what historical sessions contained;
- what broad theorem might be worth proving next.

Use those prior audits as inputs.

RL221 instead asks:

> Can the existing results be placed into a common coordinate/constraint system and jointly propagated until either the feasible set becomes empty or a very small set of missing bridges is exposed?

Treat this closer to a theorem-level SAT/SMT/constraint-intersection problem than to a historical review.

## Repository and retrieval policy

Use the repository’s current optimisation/search infrastructure aggressively.

The knowledge/session/result catalogues are lookup accelerators only and may be stale for the most recent generations. Use them to locate historical results efficiently, then open the canonical source for every load-bearing theorem, certificate, correction or scope condition.

Do not recursively re-audit or replay hundreds of historical sessions.

Use verification economy:

- trust frozen inherited proof-state ledgers after the current RL220 startup/closeout gates pass;
- selectively recover canonical theorem statements and exact interfaces;
- rerun historical expensive certificates only if a genuine unresolved dependency, verifier failure, contradiction or stop-and-repair condition requires it.

Include RL220 and the most recent post-catalogue generations directly even if the generated knowledge index has not yet caught up.

## Step 1 — Define one canonical hypothetical RL object

Construct a unified specification for a hypothetical genuine RL/nontrivial-cycle object.

Include all coordinates necessary to host the major surviving theorem families, for example where applicable:

- global cycle parameters;
- primitive/full-cycle data;
- `D`, `Q`, phase and rotation data;
- Gate-A terminal parameters;
- terminal exponent/rank;
- `H`, `J`, displacement/rank variables;
- H21 physical variables;
- e=16/root-lattice coordinates;
- prefix and phase selectors;
- exact k-windows;
- 2-adic cylinder/state data;
- physical height constraints;
- ownership/full-phase constraints;
- population/packing quantities;
- radius/rotation quantities;
- blue-family or basin-membership interfaces;
- any other variables required by currently live major theorem families.

Do not force unrelated parameterizations together incorrectly. Introduce explicit bridge maps where two theorem families use different coordinates.

## Step 2 — Convert the surviving mathematics into constraints

For every strategically significant **currently valid** result, encode its effect on the canonical hypothetical object as one or more of:

- exact equality;
- inequality;
- congruence;
- valuation condition;
- forbidden configuration;
- required configuration;
- finite certified exclusion;
- implication;
- disjunction;
- parameter range;
- structural ownership condition;
- physical realizability condition.

Every constraint must carry a scope label such as:

- global RL;
- primitive/full-D only;
- Gate A;
- Gate B;
- H21 physical only;
- e=16 only;
- arithmetic necessary condition only;
- first-Farey only;
- safe-CF only;
- owned/full-phase only;
- external computational certificate;
- exact finite certificate;
- conjectural / evidence only.

Never combine constraints whose hypotheses have not been jointly established.

## Step 3 — Remove duplicate information

A major danger is counting the same fact repeatedly in different notation.

Detect and collapse:

- coboundary-equivalent identities;
- algebraic restatements;
- consequences already implied by stronger inherited results;
- different lemmas constraining the same degree of freedom without adding information;
- historical claims superseded by corrected versions;
- demoted/false routes.

Build an **independence map** showing which surviving constraints genuinely price different freedoms of the hypothetical RL object.

This is essential.

The goal is not to accumulate hundreds of lemmas. The goal is to find the relatively small number of genuinely independent walls around RL.

## Step 4 — Search for contradiction cores

Actively test combinations of independent constraints.

Search systematically for:

- pairwise contradictions;
- triple intersections;
- four-way or small higher-order contradiction cores;
- equality + inequality conflicts;
- incompatible congruence/valuation requirements;
- mutually impossible physical and arithmetic conditions;
- radius/ownership interactions;
- H21/global-theorem interactions;
- rank/height/full-phase interactions;
- 2-adic/global-divisibility interactions;
- blue-basin/H21 exact-equality interactions;
- finite-certificate + analytic-theorem combinations.

Where exact finite propagation is possible, write small transparent verifiers/search scripts rather than relying on informal inspection.

Prefer symbolic/class-level propagation over enumeration of the full current candidate population.

## Step 5 — Fire historical global weapons at the modern H21 object

Give special priority to cross-generation interactions that earlier audits could not test because the modern H21 object did not yet exist.

In particular:

> Take the current surviving H21/e=16/root-lattice object and deliberately apply older global theorems to it.

Ask whether H21 has already fixed enough variables that previously weak global results become strong or contradictory.

Do not assume that results developed in different historical programmes are independent or incompatible; prove the bridge.

Conversely, do not assume a historical theorem applies to H21 merely because its notation can be translated.

## Step 6 — Countermodel and fake-family discrimination

Red-team every promising contradiction against the project’s known fake/generalized models and method barriers.

Especially ask:

- does the alleged contradiction genuinely consume full Collatz ownership?
- does it distinguish the generalized-increment fake families?
- does it accidentally hold for RL20-type local countermodels where global divisibility fails?
- is it merely another coboundary?
- is it using density/proximity where exact equality is required?
- is it treating arithmetic candidates as physical H21 objects?
- is it confusing necessary conditions with sufficient conditions?

Any contradiction that survives only because of a hidden scope mismatch must be rejected and recorded in the correction/barrier ledger.

## Primary success condition

The strongest success is:

> derive a genuine contradiction from a finite jointly applicable subset of currently proved/certified constraints.

If successful, isolate the **smallest defensible contradiction core** possible.

State exactly:

1. the constraints used;
2. their canonical sources;
3. their scopes;
4. the bridge statements connecting their coordinate systems;
5. the exact contradiction;
6. whether this closes Gate A, Gate B, H21, RL/nontrivial cycles, or something narrower.

Do not claim global RL closure unless every required hypothesis is established for every hypothetical RL object.

## Secondary success condition — missing bridge extraction

If the full intersection is not yet empty, identify the smallest missing bridge theorem(s) that would make it empty.

This is a major success.

The desired output should look like:

> Constraints A, B, C, D and E are jointly applicable. Their intersection would be empty if one could prove bridge X. Therefore X is not merely another interesting lemma; it is a precise closure bridge completing an already assembled contradiction core.

Rank missing bridges by **closure leverage**, not novelty.

Prefer one sharp missing implication over a broad new programme.

## Tertiary success condition — irreducible survivor model

If neither contradiction nor near-contradiction is found, construct a compact exact description of a hypothetical object satisfying every currently enforceable independent constraint.

That survivor model should expose the degrees of freedom the existing mathematics has genuinely failed to constrain.

This would establish precisely why no present super-theorem exists and prevent future sessions from unknowingly recombining redundant information.

## Required RL221 outputs

Produce at minimum:

1. **Unified RL Constraint Model**
   - canonical hypothetical-object coordinates;
   - bridge maps between theorem families.
2. **Independent Constraint Catalogue**
   - only live strategically significant constraints;
   - exact scope and provenance;
   - duplicate/coboundary equivalence classes.

4. **Contradiction-Core Search Report**
   - combinations tested;
   - exact successful contradictions or exact reasons they fail.
5. **Minimal Contradiction Core**, if found.
6. **Minimal Missing Bridge Set**, if no contradiction is yet complete.
7. **Survivor Model / Remaining Degrees of Freedom**, if applicable.
8. Exact finite verifiers for any computational intersection result.
9. Updated correction/demotion/method-barrier ledger for any apparent synthesis that collapses to known information.
10. A narrowly defined RL222 target based on the strongest concrete outcome.

## Important working style

This should be a sustained synthesis/attack session.

Do not stop after producing the unified catalogue.

The catalogue is merely setup.

Once the constraint system exists, continue actively attacking its intersections for as long as context/compute remains productive.

Do not terminate simply because several pairwise combinations fail.

Search larger connected clusters where mathematically justified.

At sensible checkpoints preserve work so that interruption does not lose progress.

## Prohibited outcomes

RL221 is not complete if it merely says:

- “Gate A and Gate B remain open”;
- “more research is required”;
- “these are the top five routes”;
- “H21 remains promising”;
- “radius 3 is a strong theorem”;
- “here is another lemma catalogue”.

Those may be observations, but they are not the purpose of this session.

The session must attempt to determine whether the **joint system** is contradictory.

## Closeout discipline

If a genuine contradiction is found, red-team it aggressively before promotion.

If it survives, classify its exact closure scope conservatively.

If no contradiction is found, make the next target the smallest concrete missing bridge exposed by the intersection analysis rather than reverting automatically to the prior RL221/RL222 conveyor target.

Preserve all frozen mathematical state and normal repository closeout rules throughout.

The guiding question for the entire session is:

> **After 220 sessions of constructing independent restrictions on RL, do the walls already touch? If not, what is the smallest missing piece that would make them touch?**
